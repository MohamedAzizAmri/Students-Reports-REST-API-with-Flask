# Students & Reports REST API (Flask)

Two in-memory lists (students, end-of-studies reports) with POST, GET all and GET
by id on each, JWT protection on the "get student" endpoints, token expiration +
refresh, and JSON error handling. There is no PUT or DELETE. Data resets every time
the server restarts.

## Run it in VS Code

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate        macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
python app.py                  # http://127.0.0.1:5000
pytest                         # run the tests
```

Then pick the interpreter in VS Code (Ctrl+Shift+P > "Python: Select Interpreter" > `.venv`).
To try requests without leaving VS Code, install the **REST Client** extension and open `requests.http`
(click "Send Request" above each request).

## Run it with Docker

```bash
cp .env.example .env          # Windows: copy .env.example .env   (then edit the values)
docker compose up --build     # API at http://127.0.0.1:5000
docker compose down           # stop it
```

Without compose:

```bash
docker build -t students-reports-api .
docker run --rm -p 5000:5000 -e ACCESS_TOKEN_MINUTES=1 -v "${PWD}/logs:/app/logs" students-reports-api
# cmd.exe: use %cd% instead of ${PWD}
```

### Parameters (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | 5000 | port the API listens on |
| `HOST_PORT` | 5000 | port opened on your machine (compose only) |
| `SECRET_KEY` | dev value | signs the tokens (set your own) |
| `ACCESS_TOKEN_MINUTES` | 5 | access token lifetime |
| `REFRESH_TOKEN_HOURS` | 24 | refresh token lifetime |
| `API_USERNAME` / `API_PASSWORD` | admin / admin123 | demo login |
| `LOG_LEVEL` | INFO | DEBUG, INFO, WARNING, ERROR |
| `LOG_FILE` | logs/app.log | where the log file is written |
| `FLASK_DEBUG` | 0 | `python app.py` only: 1 = auto-restart on save |
| `HOST` | 127.0.0.1 | `python app.py` only |

The container runs gunicorn with **one worker** on purpose: the data lives in memory, so
several workers would each hold a different copy of the students and reports.

### Error log file

Every failed request is written to `logs/app.log` (rotated at 1 MB, 3 old files kept), one line each:

```
2026-10-26 22:11:04 | WARNING  | POST /students -> 400 validation_error: Validation failed | details={'Level': ...}
```

Unexpected crashes also write the full Python traceback (the client only sees a generic 500).
Passwords and tokens are never logged. See the same lines live with `docker compose logs -f`.

## Data model

| Student     | Type / values                              |
|-------------|--------------------------------------------|
| ID_S        | integer, generated by the server           |
| FirstName   | string                                     |
| LastName    | string                                     |
| DoubleMajor | boolean                                    |
| Level       | integer 1, 2, 3 or 4 (1 = Freshman ... 4 = Senior) |

| Report      | Type / values                              |
|-------------|--------------------------------------------|
| ID_R        | integer, generated by the server           |
| Title       | string                                     |
| Type        | Mini senior project, End-of-studies project|
| K1, K2, K3  | keywords, all three required               |
| ReleaseDate | `YYYY-MM-DD`                               |
| ID_S        | the student who owns the report (required) |

## Relationship rules

- Every report belongs to exactly one student (`ID_S`, must exist).
- A single-major student can have **1** report; a `DoubleMajor` student can have **2**.
  Going over the limit returns `409 report_limit_reached`.
- `ID_S` and `ID_R` are generated by the server. Sending `ID_R`, or `ID_S` in a student body, returns a 400.

## Endpoints

| Method | URL                  | Token needed? | Notes                          |
|--------|----------------------|---------------|--------------------------------|
| POST   | `/auth/login`        | no            | `{"username","password"}` (default `admin` / `admin123`) |
| POST   | `/auth/refresh`      | no            | `{"refresh_token"}`; each refresh token works once |
| POST   | `/students`          | no            | 201 + `Location` header        |
| GET    | `/students`          | **yes**       | all students                   |
| GET    | `/students/<id>`     | **yes**       | one student                    |
| POST   | `/reports`           | no            | 201 + `Location` header        |
| GET    | `/reports`           | no            | all reports                    |
| GET    | `/reports/<id>`      | no            | one report                     |

To protect another endpoint, add `@token_required` under its route decorator.

## Tokens

- `POST /auth/login` returns an **access token** (5 minutes by default) and a **refresh token** (24 hours).
- Send the access token as `Authorization: Bearer <access_token>`.
- When it expires you get `401` with code `token_expired`. Call `/auth/refresh` with the
  refresh token to get a brand-new pair. The old refresh token is then revoked.
- Change lifetimes and credentials with environment variables: `ACCESS_TOKEN_MINUTES`,
  `REFRESH_TOKEN_HOURS`, `SECRET_KEY`, `API_USERNAME`, `API_PASSWORD`.
  Tip: set `ACCESS_TOKEN_MINUTES=1` to show expiration quickly during a demo.

## Errors

Every error is JSON with the same shape:

```json
{"error": {"status": 400, "code": "validation_error", "message": "Validation failed",
           "details": {"Level": "Must be an integer: 1, 2, 3 or 4."}}}
```

| Status | Codes                                                                  |
|--------|------------------------------------------------------------------------|
| 400    | `validation_error`, `invalid_json`, `unknown_fields`                   |
| 401    | `token_missing`, `token_invalid`, `token_expired`, `token_revoked`, `wrong_token_type`, `invalid_credentials` |
| 404    | `not_found`                                                            |
| 405    | `method_not_allowed` (includes PUT and DELETE)                         |
| 409    | `report_limit_reached`                                                 |
| 415    | `unsupported_media_type`                                               |
| 422    | `invalid_reference` (report points to a student that doesn't exist)    |
| 500    | `internal_server_error` (details are logged, never sent to the client) |
